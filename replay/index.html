    خروجی برای SIEM

    خروجی، همهٔ رخدادهای منطبق با فیلتر فعلی را شامل می‌شود. متن خام، رمزها و داده‌های آزاد رخداد در آن درج نمی‌شوند. نشانی مبدأ حفظ می‌شود.

    اگر لاگ‌های Advanced اختلاف ساعت‌های متفاوت دارند، هر بازه یا میزبان را در یک پروندهٔ جدا باز کن.

    اتصال به Wazuh

    1. برای وارد کردن پرونده، نسخهٔ JSONL استاندارد را روی میزبانی که Agent دارد قرار بده. مسیر واقعی فایل را در نمونهٔ زیر جایگزین کن و بلوک را داخل ossec_config در ossec.conf همان Agent بگذار.
    2. برای جمع‌آوری زنده، به‌جای بلوک پرونده، بلوک مربوط به هر حسگر را روی Agent همان میزبان تنظیم کن. برای Advanced مسیر واقعی json_log_file را پیدا کن. لاگ‌های زندهٔ خام ممکن است رمز آزمایشی یا ورودی حساس داشته باشند. دسترسی، مدت نگهداری و مقصد را طبق سیاست تیم محدود کن.
    3. قوانین نمونه را در local_rules.xml روی Manager ادغام کن و قبل از راه‌اندازی مجدد مطمئن شو شناسه‌ها با قوانین موجود تداخل ندارند. یک خط از خروجی استاندارد را با wazuh-logtest بررسی کن. سپس Agent و Manager مربوط را راه‌اندازی مجدد کن و در داشبورد با data.hp_product فیلتر بزن.
    تنظیم Agent برای پروندهٔ خروجی
    <localfile>
  <location>/var/log/honeypots/replay-siem.jsonl</location>
  <log_format>json</log_format>
  <only-future-events>no</only-future-events>
</localfile>

    این گزینه برای ورود محتوای موجود است. برای آزمایش از یک مسیر اختصاصی استفاده کن تا یک پرونده را چند بار وارد نکنی.

    تنظیم Agent برای حسگرهای زنده
    <localfile>
  <location>/var/log/mirageot/events.jsonl</location>
  <log_format>json</log_format>
  <label key="hp_product">mirageot</label>
</localfile>

<localfile>
  <location>/opt/advanced-honeypot/honeypot_events.jsonl</location>
  <log_format>json</log_format>
  <label key="hp_product">advanced_honeypot</label>
</localfile>
    قوانین نمونهٔ Manager
    <group name="honeypots,">
  <rule id="100560" level="3">
    <decoded_as>json</decoded_as>
    <field name="hp_product" type="pcre2">^(mirageot|advanced_honeypot)$</field>
    <description>Honeypot event from $(hp_product)</description>
    <options>no_full_log</options>
  </rule>
  <rule id="100561" level="8">
    <if_sid>100560</if_sid>
    <field name="severity" type="pcre2">^(HIGH|CRITICAL)$</field>
    <description>High-severity honeypot event from $(hp_product)</description>
    <options>no_full_log</options>
  </rule>
  <rule id="100562" level="8">
    <if_sid>100560</if_sid>
    <field name="alert_level" type="pcre2">^(HIGH|CRITICAL)$</field>
    <description>Advanced Honeypot high session alert level</description>
    <options>no_full_log</options>
  </rule>
</group>

    حذف full_log فقط روی همان فیلدِ هشدار اثر دارد. برای اشتراک‌گذاری محدود، JSONL استاندارد را استفاده کن.

    امن‌سازی پنل‌ها

    • MirageOT. console_host را روی 127.0.0.1 نگه دار. برای دسترسی مدیریتی از SSH یا شبکهٔ مدیریت استفاده کن. اگر کنسول باید روی شبکه گوش بدهد، API را با MIRAGEOT_CONSOLE_TOKEN و ورودی را با HTTPS و احراز هویت محافظت کن.
    • Advanced Honeypot. داشبورد را روی 127.0.0.1 نگه دار و از تونل SSH استفاده کن. این پنل دادهٔ حساس و امکان حذف نشست دارد. اگر از توکن داخلی استفاده می‌کنی، آن را در HONEYPOT_DASH_TOKEN بگذار. مسیرهایی که توکن را در نشانی می‌گذارند می‌توانند آن را در تاریخچه و لاگ دسترسی ثبت کنند.
    • هر دو حسگر. شبکهٔ طعمه را از شبکهٔ مدیریت و تجهیزات واقعی جدا کن. دسترسی به لاگ و دیتابیس را محدود کن و گزارش خام را روی مسیر عمومی یا GitHub قرار نده. برای اشتراک‌گذاری از خروجی محدودشده استفاده کن.
    ssh -N -L 127.0.0.1:18888:127.0.0.1:8888 admin@mirageot-host
ssh -N -L 127.0.0.1:18080:127.0.0.1:8080 admin@advanced-host

    بعد از تونل، پنل‌ها را به‌ترتیب روی 127.0.0.1:18888 و 127.0.0.1:18080 باز کن. نام میزبان و پورت را با تنظیم واقعی جایگزین کن.
